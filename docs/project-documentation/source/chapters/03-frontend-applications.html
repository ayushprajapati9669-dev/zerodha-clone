Chapter 3 — Frontend Applications & Component Architecture

3.1 Overview of Frontend Structure

The presentation tier is designed as a modular, responsive Single Page Application (SPA) built with React 19, React Router DOM 7, and Vite 8. It delivers two distinct user experiences:

  1. Public Marketing Portal (Landing Application): The institutional marketing website featuring the Zerodha brand homepage, transparent brokerage pricing calculators, ecosystem product showcases (Console, Coin, Kite Connect, Varsity), about pages, and mobile OTP signup/login interfaces.
  2. Trading Terminal (Kite Dashboard): The secure, authenticated trading dashboard providing real-time market watchlists, buy/sell order execution modals, holdings breakdown, intraday positions, ledger balance management, portfolio performance analytics, risk guard monitoring, trading journals, strategy backtesting, paper-trading competitions, and an integrated AI assistant.

3.3 Global State Management: AppContext.jsx

Application state is centralized within AppContext.jsx using React's Context API. This eliminates prop drilling across deeply nested components while maintaining reactivity across the trading terminal.

Key State Categories and Reactive Signals:

State Domain State Variables Purpose & Reactive Behavior
Authentication & User currentUser, userLoading Stores user profile (name, email, mobile, clientId, role). Polled upon mount via GET /api/auth/me.
Order Execution isTradePopupOpen, selectedStock, stockType, orderVersion Controls the trading window modal. Incrementing orderVersion triggers auto-refresh of order book and ledger.
Holdings & Positions holdings, isHoldingsLoading, holdingVersion, positionVersion Caches delivery holdings and intraday positions. Updated on order fulfillment or socket execution events.
Cash & Ledger availableBalance, usedBalance, reservedBalance, fundVersion Maintains the three-tier balance ledger. Automatically updated when orders are placed, triggered, or canceled.
Market Prices marketPrices, isMarketPricesLoading Stores latest tick data map (LTP, change, open, high, low, previous close) refreshed periodically and via WebSockets.
Notifications notifications, notificationPagination In-app notifications feed with real-time socket prepending and unread counter badges.
Visual Theme theme ('light' | 'dark' | 'system') Binds to <html data-theme="..."> and synchronizes with localStorage.

3.4 TradePopup: The Trading Window

TradePopup.jsx implements the core order placement interface replicating Zerodha's Kite Order Window:

  • Color-Coded Modals: Blue header for BUY orders, Orange header for SELL orders.
  • Product Selection: Toggle between CNC (Cash 'N Carry delivery — 100% margin required) and MIS (Margin Intraday Square-off — leverage supported, auto square-off at 3:15 PM).
  • Order Types:
    • Market Order: Executed immediately at current market LTP. Requires availableBalance >= qty * LTP.
    • Limit Order: User specifies a trigger limit price. Cash (for Buy) or stock shares (for Sell) are immediately placed into reserved status.
  • Dynamic Margin Calculator: As the user adjusts the quantity and price inputs, the component dynamically calculates required funds: Required Margin = Quantity * Price, comparing it in real time against availableBalance and showing a warning badge if funds are insufficient.
