Chapter 2 — Complete System Architecture

2.1 Overall System Architecture

The system utilizes a modern, unified full-stack architecture that cleanly separates client presentation from backend domain logic while enabling seamless single-origin execution without cross-origin resource sharing (CORS) friction.

Architectural Components Walkthrough:

  1. Browser Client Layer: The presentation tier is built with React 19 and Vite. In the original repository, two distinct Vite apps existed: frontend/ (marketing, landing pages, education) and dashboard/ (Kite trading terminal). In AI Studio and production deployment, these are unified under a single origin on port 3000, eliminating browser cross-port redirects.
  2. Unified Express Gateway & Vite Middleware: The Node.js 22 runtime server boots an Express 5 instance on port 3000. In development mode, Vite's internal development server is mounted as an Express middleware (vite.middlewares), handling HMR and JSX on-the-fly. In production, pre-compiled static assets in dist/ are served directly with an SPA catch-all route.
  3. Middleware Pipeline: Incoming HTTP requests pass through security and parsing middlewares:
    • cors({ origin: true, credentials: true }): Permits secure credentialed requests.
    • cookieParser(): Extracts the token cookie containing the signed JSON Web Token.
    • isLoggedInMiddleware.js: Decodes JWT, validates session active status, and checks tokenVersion to support global logout.
    • orderValidation.js / validateUser.js: Joi schema validation catching invalid inputs before controllers execute.
  4. Domain Services & State Machines: Business logic is isolated from HTTP handlers into dedicated services (createOrderServices.js, tournamentService.js, aiService.js, trueDataService.js).
  5. Persistence Layer: MongoDB stores structured documents across 15 schemas. When executing orders or balance modifications, Mongoose leverages native multi-document transactions with atomic session rollbacks.
  6. Real-Time Event Multiplexer (Socket.IO): Attached to the native HTTP server instance, Socket.IO routes events into isolated rooms (user:{userId} and tournament:{id}).

2.2 HTTP Request Lifecycle

When a user initiates an action in the UI (for example, clicking "Buy 10 Reliance CNC at ₹2,525"):

  1. HTTP Transmission: The Axios client transmits a POST /api/orders request with { withCredentials: true }, automatically attaching the browser's HTTP-only cookie.
  2. Middleware Verification: Express matches the route. isLoggedIn extracts the cookie, runs jwt.verify(token, JWT_SECRET), queries the user model to verify tokenVersion, and attaches req.user = { userId, role, status }.
  3. Payload Validation: The Joi validation middleware parses req.body against orderValidationSchema.js. If validation fails (e.g., negative quantity or missing symbol), a 400 Bad Request is returned immediately without touching the database.
  4. Controller Execution: orderController.js invokes createOrderServices.js, passing the sanitized payload and authenticated userId.
  5. Transactional Execution: A MongoDB transaction session begins:
    • Calculates required capital: qty * price.
    • Checks availableBalance >= requiredAmount.
    • Updates user ledger: availableBalance -= requiredAmount, usedBalance += requiredAmount.
    • Creates/updates Holding or Position record.
    • Inserts Order record with status completed.
  6. Event Dispatch & Response: Upon successful commit, a notification is written, Socket.IO emits new-notification to user:{userId}, and HTTP 201 Created is returned to the client. The frontend AppContext receives the response and triggers state re-fetching.

2.3 Real-Time WebSocket & Socket.IO Flow

The real-time infrastructure provides sub-second push updates for:

  • Order Execution Notifications: When limit orders trigger in the background via live market ticks, user alerts fire without polling.
  • Price Alerts: Triggered when a stock reaches a user-defined price ceiling or floor.
  • Tournament Leaderboards: Real-time rank and ROI calculations broadcast to all active competitors inside tournament:{id}.
