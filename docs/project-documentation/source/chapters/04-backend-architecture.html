Chapter 4 — Backend Architecture & Request Pipeline

4.1 Backend Architectural Pattern

The backend is engineered using Node.js 22 and Express 5.2 adhering to a layered Controller-Service-Repository architectural pattern. The codebase strictly separates HTTP transport concerns (status codes, headers, cookie parsing) from domain trading rules (balance math, limit order triggers, inventory locking) and persistence layers (MongoDB Mongoose models).

4.2 Middleware Pipeline Execution Order

Every incoming HTTP request traverses an ordered sequence of middlewares before reaching route controllers: 

Incoming Request
      │
      ▼
1. cors({ origin: true, credentials: true })
   ├── Validates allowed origins
   └── Allows Authorization headers and cookies
      │
      ▼
2. bodyParser.json()
   └── Parses JSON request bodies into req.body
      │
      ▼
3. cookieParser()
   └── Extracts browser cookies into req.cookies (notably req.cookies.token)
      │
      ▼
4. passport.initialize()
   └── Sets up Passport authentication strategy framework
      │
      ▼
5. Route-Specific Middlewares:
   ├── validateUser / orderValidation (Joi schema validation on req.body)
   ├── isLoggedInMiddleware (JWT verification, session status, tokenVersion check)
   └── adminMiddleware (Verifies req.user.role === 'admin')
      │
      ▼
6. Domain Controller & Service
   └── Executes business logic, database transactions, socket emissions
      │
      ▼
7. Global Error Handler / Offline Fallback Middleware
   └── Catches uncaught errors, Mongoose connection drops, and network timeouts

4.4 Controller vs. Service Decoupling

Rather than writing SQL/Mongo queries directly inside controller files, complex domain operations are delegated to service modules:

  • createOrderServices.js: Coordinates validation, price retrieval, capital checks, and MongoDB transaction sessions.
  • checkPendingLimitOrders.js: Invoked whenever fresh market ticks arrive; iterates over active pending limit orders to evaluate whether trigger prices are met.
  • tournamentService.js: Manages tournament lifecycles (scheduled -> active -> completed), matches virtual limit orders against live market ticks, and recalculates leaderboards.
  • aiService.js: Formulates prompt strings, enforces safety instructions, and handles communication with Google GenAI SDK.
