Chapter 6 — Database Architecture & Schema Design

6.1 Database Architecture Overview

Persistence is managed by MongoDB using the Mongoose Object Data Modeling (ODM) framework. The schema design models high-frequency trading data, delivery equity holdings, multi-day ledger balances, audit trails, and virtual tournament portfolios.

6.2 Schema Specifications

1. User Model (models/UserModel.js)

Master account entity storing personal details, authentication credentials, and access control roles.

FieldTypeConstraints & DefaultsDescription
nameStringRequired, trimUser full legal name.
emailStringRequired, unique, lowercase, trimAccount email address.
mobileStringRequired, unique, trim10-digit verified Indian phone number.
passwordStringRequired, select: falsebcrypt-hashed password (excluded from default queries).
clientIdStringRequired, unique, uppercase6-character broker trading ID (e.g. ZR9669).
roleStringenum: ['trader', 'admin'], default: 'trader'Access role for authorization.
statusStringenum: ['active', 'suspended'], default: 'active'Account status.
tokenVersionNumberdefault: 0Session version counter for revocation.
lastLoginDatedefault: Date.nowTimestamp of last authenticated session.

2. Funds Model (models/FundsModel.js)

Maintains the three-tier balance ledger required for atomic order execution and margin management.

FieldTypeConstraints & DefaultsDescription
userIdObjectId / StringRequired, ref: 'User', unique indexAssociated trader ID.
availableBalanceNumberdefault: 100000, min: 0Liquid capital available for new trades or withdrawal.
usedBalanceNumberdefault: 0Capital currently deployed in active holdings or open positions.
reservedBalanceNumberdefault: 0, min: 0Capital locked for pending buy limit orders.

3. Orders Model (models/OrdersModel.js)

Comprehensive order execution ledger tracking state transitions from pending to filled or canceled.

FieldTypeConstraints & DefaultsDescription
userIdObjectId / StringRequired, ref: 'User', indexTrader placing the order.
symbolStringRequired, uppercase, trimNSE/BSE ticker symbol (e.g. RELIANCE).
qtyNumberRequired, min: 1Number of shares to execute.
priceNumberRequired, min: 0.05Order execution price (or limit trigger price).

orderTypeStringenum: ['MARKET', 'LIMIT'], default: 'MARKET'Order trigger type.
productStringenum: ['CNC', 'MIS'], default: 'CNC'Equity delivery vs. Intraday margin.
statusStringenum: ['pending', 'processing', 'completed', 'cancelled']Execution lifecycle state.
reservedAmountNumberdefault: 0Cash amount locked while in pending status.
reservationReleasedBooleandefault: falseFlag ensuring reserved funds are released exactly once.

4. Holdings Model (models/HoldingsModel.js)

Long-term equity inventory acquired through Cash 'N Carry (CNC) delivery purchases.

FieldTypeConstraints & DefaultsDescription

6. Additional Specialized Models

  • FundTransactionModel: Double-entry deposit and withdrawal ledger entries with unique timestamps.
  • TournamentModel: Competition configurations (start time, end time, entry fee, initial virtual balance).
  • TournamentParticipationModel: User tournament entries tracking virtual portfolio, rank, and ROI.
  • TournamentOrderModel: Order records scoped specifically to tournament competition portfolios.
  • ChatModel: Threaded AI conversation messages between trader and Gemini assistant.
  • WatchlistListModel: User watchlists containing ordered arrays of tracked symbols.
  • PriceAlertModel: Price threshold triggers (above/below condition checks).
  • RiskSettingsModel: Risk Guard parameters (maximum daily loss, position limits, leverage constraints).
  • JournalModel: Trade reflection notes with psychological tags (FOMO, Greed, Disciplined).
  • BacktestHistoryModel: Stored strategy backtest results with calculated financial KPIs.
